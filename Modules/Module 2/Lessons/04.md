# Introduction

Imagine a customer table where:

* Two customers have the same ID
* An email address appears multiple times
* A customer's age is -25
* An order references a customer that doesn't exist

These situations create bad data.

To prevent such problems, databases use **constraints**.

Constraints are rules that SQL Server enforces automatically.

---

# What is a Constraint?

A constraint is a rule applied to a column or table.

Constraints help:

✅ Ensure data accuracy

✅ Prevent invalid entries

✅ Maintain consistency

✅ Enforce business rules

✅ Support relationships

---

# Why Constraints Matter

Without constraints:

```text id="con001"
CustomerID = 1
CustomerID = 1
CustomerID = 1
```

Duplicate records become possible.

---

Without constraints:

```text id="con002"
Age = -100
```

Invalid values can be stored.

---

Without constraints:

```text id="con003"
Order references CustomerID 999
```

Relationships become broken.

# PRIMARY KEY Constraint

A PRIMARY KEY uniquely identifies each row in a table.

---

# Rules of a Primary Key

A primary key:

* Must be unique
* Cannot contain NULL values
* Must identify exactly one row

---

# Example

```sql id="con005"
CREATE TABLE Students (
    StudentID INT PRIMARY KEY,
    FirstName VARCHAR(100)
);
```

---

# Valid Data

| StudentID | FirstName |
| --------- | --------- |
| 1         | John      |
| 2         | Sarah     |

---

# Invalid Data

| StudentID | FirstName |
| --------- | --------- |
| 1         | John      |
| 1         | Sarah     |

Duplicate primary key values are not allowed.

---

# PRIMARY KEY Visualization

```text id="con006"
Students
│
├── StudentID (PK)
├── FirstName
└── LastName
```

---

# IDENTITY and Primary Keys

SQL Server commonly uses:

```sql id="con007"
StudentID INT IDENTITY(1,1) PRIMARY KEY
```

Meaning:

```text id="con008"
1
2
3
4
5
```

SQL Server automatically generates values.

---

# UNIQUE Constraint

Ensures that all values in a column are unique.

---

# Example

```sql id="con009"
CREATE TABLE Users (
    UserID INT PRIMARY KEY,
    Email VARCHAR(255) UNIQUE
);
```

---

# Valid Example

| Email                                     |
| ----------------------------------------- |
| [john@email.com](mailto:john@email.com)   |
| [sarah@email.com](mailto:sarah@email.com) |

---

# Invalid Example

| Email                                   |
| --------------------------------------- |
| [john@email.com](mailto:john@email.com) |
| [john@email.com](mailto:john@email.com) |

Duplicate values are rejected.

---

# When to Use UNIQUE

Common examples:

```text id="con010"

```

# NOT NULL Constraint

Prevents empty values.

---

# Example

```sql id="con011"
CREATE TABLE Employees (
    EmployeeID INT PRIMARY KEY,
    FirstName VARCHAR(100) NOT NULL
);
```

---

# Valid

| FirstName |
| --------- |
| John      |

---

# Invalid

```text id="con012"
NULL
```

SQL Server rejects the row.

---

# Why NOT NULL Matters

Certain information is mandatory.

Examples:

```text id="con013"
Customer Name
Email
Order Date
Product Name
```

These should not be empty.

---

# DEFAULT Constraint

Provides a value automatically if none is supplied.

---

# Example

```sql id="con014"
RegistrationDate DATE
DEFAULT GETDATE()
```

---

# Insert Example

```sql id="con015"
INSERT INTO Members (MemberName)
VALUES ('John');
```

SQL Server automatically inserts:

```text id="con016"
Today's Date
```

---

# Full Example

```sql id="con017"
CREATE TABLE Members (
    MemberID INT PRIMARY KEY,
    MemberName VARCHAR(100),
    RegistrationDate DATE DEFAULT GETDATE()
);
```

---

# Benefits of DEFAULT

* Reduces manual input
* Ensures consistency
* Simplifies inserts

---

# CHECK Constraint

Enforces business rules.

---

# Example

Age should be between 18 and 60.

```sql id="con018"
Age INT CHECK (Age BETWEEN 18 AND 60)
```

---

# Valid Values

```text id="con019"
18
25
45
60
```

---

# Invalid Values

```text id="con020"
15
75
-5
```

Rejected automatically.

---

# More CHECK Examples

---

## Product Price

```sql id="con021"
Price DECIMAL(10,2)
CHECK (Price > 0)
```

---

## Rating

```sql id="con022"
Rating INT
CHECK (Rating BETWEEN 1 AND 5)
```

---

## Salary

```sql id="con023"

```

# FOREIGN KEY Constraint

Creates relationships between tables.

---

# Example

Customers table:

```sql id="con024"
CREATE TABLE Customers (
    CustomerID INT PRIMARY KEY,
    CustomerName VARCHAR(100)
);
```

---

Orders table:

```sql id="con025"
CREATE TABLE Orders (
    OrderID INT PRIMARY KEY,
    CustomerID INT,
    
    FOREIGN KEY (CustomerID)
    REFERENCES Customers(CustomerID)
);
```

---

# Relationship Diagram

```text id="con026"
Customers
---------
CustomerID (PK)

       │
       ▼

Orders
---------
OrderID
CustomerID (FK)
```

---

# Why Foreign Keys Matter

They ensure:

* Valid relationships
* Better integrity
* Consistent data

---

# Valid Example

Customer exists:

```text id="con027"
CustomerID = 1
```

Order:

```text id="con028"
CustomerID = 1
```

Allowed.

---

# Invalid Example

Order references:

```text id="con029"
CustomerID = 999
```

Customer doesn't exist.

Insert fails.

# Building a Proper Table

Example:

```sql id="con030"
CREATE TABLE Members (
    MemberID INT IDENTITY(1,1) PRIMARY KEY,
    
    FirstName VARCHAR(100) NOT NULL,
    
    LastName VARCHAR(100) NOT NULL,
    
    Email VARCHAR(255) UNIQUE,
    
    Age INT CHECK (Age >= 18),
    
    RegistrationDate DATE DEFAULT GETDATE()
);
```

# Common Constraint Mistakes

---

## Missing Primary Keys

Bad:

```sql id="con034"
CREATE TABLE Customers (
    Name VARCHAR(100)
);
```

---

Better:

```sql id="con035"
CREATE TABLE Customers (
    CustomerID INT PRIMARY KEY,
    Name VARCHAR(100)
);
```

---

## Forgetting NOT NULL

Bad:

```sql id="con036"
FirstName VARCHAR(100)
```

Allows NULL values.

---

Better:

```sql id="con037"
FirstName VARCHAR(100) NOT NULL
```

---

## Missing CHECK Constraints

Bad:

```sql id="con038"
Age INT
```

Allows:

```text id="con039"
-500
```

---

Better:

```sql id="con040"
Age INT CHECK (Age > 0)
```

# Real-World Example
