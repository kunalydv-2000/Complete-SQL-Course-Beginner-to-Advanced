In Module 01, you learned what databases are and why they are important.

Before we can create tables, insert data, or write queries, we need a database container to store everything.

---

# What is a Database?

A database is a structured container that stores related tables, views, procedures, functions, and other objects.

Example:

```text
LibraryManagementSystem
│
├── Books
├── Members
├── Authors
└── BorrowRecords
```

The database acts as the top-level container.

---

# Database vs Table

Many beginners confuse databases and tables.

| Database              | Table              |
| --------------------- | ------------------ |
| Collection of objects | Collection of rows |
| Contains many tables  | Stores data        |
| Top-level container   | Child object       |

---

## Example

### Database

```text
LibraryManagementSystem
```

Contains:

```text
Books
Members
Authors
Reservations
```

Each of these is a table.

---

# Why Create Separate Databases?

Organizations often use multiple databases.

Example:

```text
CompanyServer
│
├── HRDB
├── SalesDB
├── InventoryDB
└── FinanceDB
```

Benefits:

* Better organization
* Improved security
* Easier maintenance
* Reduced complexity

# SQL Server Databases

SQL Server stores databases inside a database engine.

A single SQL Server instance can contain many databases.

Example:

```text
SQL Server Instance
│
├── LibraryDB
├── SchoolDB
├── HospitalDB
└── InventoryDB
```

---

# System Databases

SQL Server includes several built-in databases.

| Database | Purpose                     |
| -------- | --------------------------- |
| master   | Stores server configuration |
| model    | Template database           |
| msdb     | SQL Server Agent data       |
| tempdb   | Temporary objects           |

---

# User Databases

Databases created by users.

Examples:

```text
LibraryManagementSystem
StudentManagementSystem
InventoryDB
```

---

# Creating a Database

SQL Server uses the CREATE DATABASE statement.

Syntax:

```sql
CREATE DATABASE DatabaseName;
```

---

# Example

```sql
CREATE DATABASE LibraryManagementSystem;
```

This creates a new database.

---

# Executing in SSMS

Open:

```text
SQL Server Management Studio
```

Create a new query window.

Run:

```sql
CREATE DATABASE LibraryManagementSystem;
```

---

# Verify Creation

Refresh Databases.

You should see:

```text
Databases
│
└── LibraryManagementSystem
```

---

# Using a Database

After creation:

```sql
USE LibraryManagementSystem;
GO
```

This tells SQL Server to use the database.

---

# Database Naming Conventions

Good naming conventions improve readability.

---

## Recommended

```text
LibraryManagementSystem
SalesDB
InventoryManagement
```

---

## Avoid

```text
Database1
Test123
MyDBNewFinal
```

---

# Naming Best Practices

### Use Meaningful Names

Good:

```text
HospitalManagementSystem
```

Bad:

```text
HMS1
```

---

### Avoid Spaces

Bad:

```text
Library Management System
```

Good:

```text
LibraryManagementSystem
```

---

### Be Consistent

Choose one convention:

```text
PascalCase
```

or

```text
snake_case
```

# Common Errors

---

## Database Already Exists

Error:

```text
Database already exists.
```

Solution:

Choose a different name or drop the existing database.

---

## Missing Permissions

Error:

```text
CREATE DATABASE permission denied.
```

Solution:

Contact the database administrator.
