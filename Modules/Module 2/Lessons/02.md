# Introduction

Every piece of information stored in a database has a type.

For example:

| Value      | Data Type |
| ---------- | --------- |
| 101        | Integer   |
| John Smith | Text      |
| 2025-06-01 | Date      |
| 499.99     | Decimal   |
| True       | Boolean   |

SQL Server needs to know the type of data that will be stored in each column.

This is where **Data Types** become important.

---

# What is a Data Type?

A data type defines:

* What kind of data can be stored
* How much storage space is required
* What operations can be performed

Think of a data type as a container.

```text
INT      → Whole Numbers
VARCHAR  → Text
DATE     → Dates
DECIMAL  → Numbers with Decimals
BIT      → True/False
```

---

# Why Are Data Types Important?

Choosing the correct data type helps:

✅ Save storage space

✅ Improve performance

✅ Maintain data quality

✅ Prevent invalid entries

✅ Improve query speed

---

# Example

Suppose Age is stored as:

```sql
Age VARCHAR(50)
```

Problem:

```text
Twenty Five
Thirty
ABC
```

could be stored.

---

Better:

```sql
Age INT
```

Now only valid numbers can be stored.

---

# Categories of Data Types

SQL Server data types can be grouped into:

```text
Data Types
│
├── Numeric
├── Character
├── Date & Time
├── Logical
└── Special Types
```

---

# Numeric Data Types

Used for numbers.

---

# INT

Stores whole numbers.

Range:

```text
-2,147,483,648
to
 2,147,483,647
```

Example:

```sql
CustomerID INT
```

---

# SMALLINT

Stores smaller whole numbers.

Example:

```sql
Age SMALLINT
```

---

# BIGINT

Stores very large numbers.

Example:

```sql
TransactionID BIGINT
```

Used in:

* Banking systems
* Large enterprise applications

---

# Decimal Numbers

Some values require decimal places.

Examples:

```text
19.99
100.50
2500.75
```

---

# DECIMAL

Syntax:

```sql
DECIMAL(precision, scale)
```

Example:

```sql
Salary DECIMAL(10,2)
```

Meaning:

```text
99999999.99
```

Maximum 10 digits.

2 digits after decimal.

---

# Example Table

| Value        | Valid |
| ------------ | ----- |
| 1000.50      | Yes   |
| 25.99        | Yes   |
| 123456789.00 | No    |

---

# Character Data Types

Used for text.

---

# CHAR

Fixed-length text.

Example:

```sql
Gender CHAR(1)
```

Values:

```text
M
F
```

Always reserves specified space.

---

# VARCHAR

Variable-length text.

Example:

```sql
FirstName VARCHAR(50)
```

Stores:

```text
John
Sarah
David
```

Uses only required space.

---

# CHAR vs VARCHAR

| CHAR         | VARCHAR         |
| ------------ | --------------- |
| Fixed Length | Variable Length |
| Faster       | More Flexible   |
| Wastes Space | Saves Space     |

---

## Example

```sql
Gender CHAR(1)
```

Good choice.

---

```sql
FirstName VARCHAR(100)
```

Good choice.

---

# Common VARCHAR Columns

```sql
FirstName VARCHAR(50)

```

---

# Date and Time Data Types

Used for storing dates and times.

---

# DATE

Stores only a date.

Example:

```sql
BirthDate DATE
```

Value:

```text
2025-06-01
```

---

# TIME

Stores only time.

Example:

```sql
MeetingTime TIME
```

Value:

```text
14:30:00
```

---

# DATETIME

Stores date and time together.

Example:

```sql
OrderDate DATETIME
```

Value:

```text
2025-06-01 14:30:00
```

---

# Example

| Data Type | Example             |
| --------- | ------------------- |
| DATE      | 2025-06-01          |
| TIME      | 10:30:00            |
| DATETIME  | 2025-06-01 10:30:00 |

---

# Logical Data Types

Used for True/False values.

---

# BIT

Stores:

```text
0 = False
1 = True
```

Example:

```sql
IsActive BIT
```

Possible values:

```text
0
1
```

---

# Real-World Examples

### Employee Table

```sql

```

---

### Customer Table

```sql
EmailVerified BIT
```

---

# MONEY


# Choosing the Correct Data Type

---

## Customer Table

```sql
CustomerID INT
FirstName VARCHAR(100)
LastName VARCHAR(100)
Email VARCHAR(255)
BirthDate DATE
IsActive BIT
```

---

# Bad Design Example

```sql
CustomerID VARCHAR(50)
Age VARCHAR(20)
Salary VARCHAR(50)
```

Problems:

* Wasted space
* Slower queries
* Poor validation

---

# Good Design Example

```sql
CustomerID INT
Age INT
Salary DECIMAL(10,2)
```

---

# Data Type Selection Guidelines

---

## Use INT For

* IDs
* Quantities
* Counts

Example:

```sql
StudentID INT
```

---

## Use VARCHAR For

* Names
* Emails
* Addresses

Example:

```sql
Email VARCHAR(255)
```

---

## Use DATE For

* Birth dates
* Joining dates
* Order dates

Example:

```sql
JoiningDate DATE
```

---

## Use DECIMAL For

* Prices
* Salaries
* Revenue

Example:

```sql
Price DECIMAL(10,2)
```

---

## Use BIT For

* Yes/No values
* True/False values

Example:

```sql
IsAvailable BIT
```

---

# Sample Table Design

```sql
CREATE TABLE Employees (
    EmployeeID INT,
    FirstName VARCHAR(100),
    LastName VARCHAR(100),
    BirthDate DATE,
    Salary DECIMAL(10,2),
    IsActive BIT
);
```

---

# Common Beginner Mistakes

---

## Using VARCHAR for Everything

Bad:

```sql
Age VARCHAR(10)
```

---

Better:

```sql
Age INT
```

---

## Using CHAR for Names

Bad:

```sql
FirstName CHAR(100)
```

Wastes storage.

---

Better:

```sql
FirstName VARCHAR(100)
```

---

## Using INT for Currency

Bad:

```sql
Price INT
```

Cannot store:

```text
19.99
```

---

Better:

```sql
Price DECIMAL(10,2)
```

---

# Real-World Example

Online Store Products Table:

```sql
CREATE TABLE Products (
    ProductID INT,
    ProductName VARCHAR(200),
    Price DECIMAL(10,2),
    StockQuantity INT,
    IsAvailable BIT,
    CreatedDate DATE
);
```
