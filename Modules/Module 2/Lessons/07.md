# Introduction

Data changes over time.

Organizations may need to:

* Remove inactive users
* Delete cancelled orders
* Remove duplicate records
* Archive old information

SQL Server uses the **DELETE** statement to remove records from tables.

Deleting data is one of the most powerful and dangerous database operations.

---

# What is DELETE?

The DELETE statement removes rows from a table.

Think of it as:

```text id="del001"
Table
   ↓
Select Rows
   ↓
Delete Rows
   ↓
Updated Table
```

---

| StudentID | FirstName |
| --------- | --------- |

| 3         | David     |

Delete David:

| StudentID | FirstName |
| --------- | --------- |

# DELETE Syntax

Basic syntax:

```sql id="del002"
DELETE FROM TableName
WHERE Condition;
```

---

# Example

```sql id="del003"
DELETE FROM Students
WHERE StudentID = 3;
```

Meaning:

```text id="del004"
Find StudentID = 3
Delete the row
```

# Why WHERE is Critical

The WHERE clause controls which rows are removed.

Without WHERE:

```sql id="del009"
DELETE FROM Students;
```

---

Result:

```text id="del010"
All rows deleted
```

The table remains, but every record is removed.

---

# Safe Deletion Process

Before deleting:

```sql id="del011"
SELECT *
FROM Students
WHERE StudentID = 3;
```

Verify the correct row.

Then:

```sql id="del012"
DELETE FROM Students
WHERE StudentID = 3;
```

# DELETE vs TRUNCATE

Many beginners confuse these commands.

---

# DELETE

Removes selected rows.

Example:

```sql id="del023"
DELETE FROM Students
WHERE StudentID = 1;
```

---

Characteristics:

✅ Uses WHERE

✅ Removes selected rows

✅ Can be rolled back in transactions

---

# TRUNCATE

Removes all rows instantly.

Example:

```sql id="del024"
TRUNCATE TABLE Students;
```

---

Characteristics:

✅ Faster

✅ Removes all rows

❌ Cannot use WHERE

---

# DELETE vs TRUNCATE Comparison

| Feature               | DELETE | TRUNCATE |
| --------------------- | ------ | -------- |
| WHERE Supported       | Yes    | No       |
| Removes Selected Rows | Yes    | No       |
| Removes All Rows      | Yes    | Yes      |
| Faster                | No     | Yes      |
| Resets Identity       | No     | Yes      |

---

# DELETE vs DROP

---

# DELETE

```sql id="del025"
DELETE FROM Students;
```

Removes rows.

Table remains.

---

# DROP

```sql id="del026"
DROP TABLE Students;
```

Removes:

* Table
* Structure
* Data

Everything is deleted.

---

# Comparison

| Command  | Removes Data | Removes Table |
| -------- | ------------ | ------------- |
| DELETE   | Yes          | No            |
| TRUNCATE | Yes          | No            |
| DROP     | Yes          | Yes           |

# Foreign Key Considerations

Suppose:

```text id="del027"
Customers
    │
    ▼
Orders
```

---

Attempt:

```sql id="del028"
DELETE FROM Customers
WHERE CustomerID = 1;
```

---

If related orders exist:

```text id="del029"
Delete may fail
```

because of foreign key constraints.

---

# Example

### Customers

| CustomerID |
| ---------- |
| 1          |

### Orders

| OrderID | CustomerID |
| ------- | ---------- |
| 101     | 1          |

Deleting CustomerID 1 may violate referential integrity.

---

# Soft Delete Concept

Many organizations do not physically delete records.

Instead:

```sql id="del030"
IsActive BIT
```

---

Example:

```sql id="del031"
UPDATE Members
SET IsActive = 0
WHERE MemberID = 1;
```

---

Benefits:

✅ Historical records preserved

✅ Easier auditing

✅ Safer recovery

# Common DELETE Mistakes

---

## Missing WHERE Clause

Bad:

```sql id="del033"
DELETE FROM Customers;
```

Deletes all records.

---

## Wrong Condition

Bad:

```sql id="del034"
DELETE FROM Students
WHERE StudentID = 999;
```

No matching row.

Nothing happens.

---

## Not Verifying Data

Bad Practice:

```sql id="del035"
DELETE FROM Orders
WHERE OrderDate < '2024-01-01';
```

Without checking affected rows.

---

Better:

```sql id="del036"
SELECT *
FROM Orders
WHERE OrderDate < '2024-01-01';
```

Verify first.
