# Introduction

In previous modules, you learned how to write queries using:

```sql
SELECT
WHERE
GROUP BY
HAVING
ORDER BY
JOINS
SUBQUERIES
```

These queries help retrieve information from database tables.

However, in enterprise environments, the same queries are often executed repeatedly.

Example:

```text
Book Catalog Report

Member Activity Report

Publisher Performance Report

Inventory Dashboard
```

Instead of rewriting the same query repeatedly, SQL provides:

```text
Views
```

---

# What is a View?

A View is a virtual table based on a SQL query.

Unlike a normal table:

```text
A View does not store data itself.
```

It stores:

```text
A SELECT statement
```

that retrieves data from underlying tables.

---

### Simplicity

### Security

Restrict access to sensitive columns.

---

### Consistency

Everyone uses the same business logic.

# Real-World Example

Suppose management frequently requests:

```text
Book Title

Category

Publisher

Price
```

---

Without a View:

```sql
SELECT
    B.Title,
    C.CategoryName,
    P.PublisherName,
    B.BookPrice
FROM Books B
INNER JOIN Categories C
    ON B.CategoryID = C.CategoryID
INNER JOIN Publishers P
    ON B.PublisherID = P.PublisherID;
```

Every report writer must repeat this query.

---

Using a View:

```sql
CREATE VIEW vw_BookCatalog
AS
SELECT
    B.Title,
    C.CategoryName,
    P.PublisherName,
    B.BookPrice
FROM Books B
INNER JOIN Categories C
    ON B.CategoryID = C.CategoryID
INNER JOIN Publishers P
    ON B.PublisherID = P.PublisherID;
```

---

Now users simply run:

```sql
SELECT *
FROM vw_BookCatalog;
```

---

# What Makes a View "Virtual"?

A View does not store data physically.

The data remains inside:

```text
Books

Categories

Publishers
```

---

When the View executes:

```text
View Query Runs
        ↓
Data Retrieved
        ↓
Results Returned
```

---

# View Syntax

Basic Structure:

```sql
CREATE VIEW ViewName
AS
SELECT
    Column1,
    Column2
FROM TableName;
```

---

Example

```sql
CREATE VIEW vw_AllBooks
AS
SELECT
    BookID,
    Title,
    BookPrice
FROM Books;
```

---

# Using a View

After creation:

```sql
SELECT *
FROM vw_AllBooks;
```

---

A View behaves like a table.

---

# View vs Table

| Feature          | View | Table |
| ---------------- | ---- | ----- |
| Stores Data      | No   | Yes   |
| Physical Storage | No   | Yes   |
| Based on Query   | Yes  | No    |
| Reusable         | Yes  | Yes   |
| Virtual Object   | Yes  | No    |

# Benefits of Views

### Simplified Queries

Users write:

```sql
SELECT *
FROM vw_BookCatalog;
```

Instead of complex joins.

---

### Improved Security

Expose only required columns.

---

### Easier Maintenance

Update the view once.

All reports benefit.

---

### Consistent Reporting

Everyone sees the same results.

---

# Common Types of Views

### Simple View

Based on one table.

```sql
CREATE VIEW vw_Books
AS
SELECT *
FROM Books;
```

---

### Complex View

Based on joins.

```sql
Books
+
Publishers
+
Categories
```

---

### Reporting View

Designed for dashboards and analytics.

# Common Beginner Mistakes

---

## Treating Views as Tables

Views do not store data.

---

## Creating Unnecessary Views

Avoid creating hundreds of small views.

---

## Poor Naming

Bad:

```text
View1
```

Better:

```text
vw_BookCatalog
```

---

## Using SELECT *

Avoid:

```sql
SELECT *
```

inside production views.
