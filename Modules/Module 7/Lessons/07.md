# Introduction

In previous lessons, you learned how to create Stored Procedures.

Example:

```sql id="ip001"
CREATE PROCEDURE GetAllBooks
AS

    SELECT *
```

---

This procedure always returns:

```text id="ip002"
All Books
```

---

But business users often need:

```text id="ip003"
Books From A Specific Category

Books From A Specific Publisher

Specific Members

Specific Authors
```

---

To make procedures flexible, SQL uses:

```text id="ip004"
Input Parameters
```

# What is an Input Parameter?

An Input Parameter is a variable passed into a Stored Procedure at execution time.

It allows the procedure to:

```text id="ip005"
Receive Input

Filter Data

Customize Results
```

---

# Visual Representation

```text id="ip006"
User Input
      ↓
Stored Procedure
      ↓
Filtered Query
      ↓
Results
```

---

# Basic Syntax

```sql id="ip007"
CREATE PROCEDURE ProcedureName
    @ParameterName DataType
AS
BEGIN

    SQL Statements

END;
```

---

# Example 1: Filter Books by Category

Business Requirement:

```text id="ip008"
Display books from a selected category.
```

---

Procedure:

```sql id="ip009"
CREATE PROCEDURE GetBooksByCategory
    @CategoryID INT
AS
BEGIN

    SELECT
        BookID,
        Title,
        BookPrice
    FROM Books
    WHERE CategoryID = @CategoryID;

END;
```

---

Execute:

```sql id="ip010"
EXEC GetBooksByCategory
    @CategoryID = 1;
```

---

Result

| BookID | Title            | Price |
| ------ | ---------------- | ----- |
| 1      | SQL Fundamentals | 499   |
| 5      | Database Design  | 699   |

---

# Example 4: Search Books by Title

```sql id="ip020"
CREATE PROCEDURE SearchBooks
    @Title VARCHAR(100)
AS
BEGIN

    SELECT
        BookID,
        Title,
        BookPrice
    FROM Books
    WHERE Title = @Title;

END;
```

---

Execute:

```sql id="ip021"
EXEC SearchBooks
    @Title = 'SQL Fundamentals';
```

---

# Example 5: Search Books Using LIKE

```sql id="ip022"
CREATE PROCEDURE SearchBooksByKeyword
    @Keyword VARCHAR(100)
AS
BEGIN

    SELECT
        BookID,
        Title
    FROM Books
    WHERE Title LIKE '%' + @Keyword + '%';

END;
```

---

Execute:

```sql id="ip023"
EXEC SearchBooksByKeyword
    @Keyword = 'SQL';
```

---

Result:

```text id="ip024"
SQL Fundamentals

Advanced SQL

SQL Server Administration
```

# Example 6: Filter Books by Category and Price

```sql id="ip025"
CREATE PROCEDURE GetBooksByCategoryAndPrice
    @CategoryID INT,
    @MaxPrice DECIMAL(10,2)
AS
BEGIN

    SELECT
        BookID,
        Title,
        BookPrice
    FROM Books
    WHERE CategoryID = @CategoryID
      AND BookPrice <= @MaxPrice;

END;
```

---

Execute:

```sql id="ip026"
EXEC GetBooksByCategoryAndPrice
    @CategoryID = 1,
    @MaxPrice = 700;
```

# Default Parameter Values

Parameters can have defaults.

---

Example:

```sql id="ip029"
CREATE PROCEDURE GetBooks
    @CategoryID INT = 1
AS
BEGIN

    SELECT *
    FROM Books
    WHERE CategoryID = @CategoryID;

END;
```

---

Execute without value:

```sql id="ip030"
EXEC GetBooks;
```

---

SQL uses:

```text id="ip031"
CategoryID = 1
```

# Parameter Validation

Example:

```sql id="ip039"
CREATE PROCEDURE GetMemberByID
    @MemberID INT
AS
BEGIN

    IF @MemberID <= 0
    BEGIN
        PRINT 'Invalid Member ID';
        RETURN;
    END

    SELECT *
    FROM Members
    WHERE MemberID = @MemberID;

END;
```

# Common Beginner Mistakes

---

## Missing Data Type

Bad:

```sql id="ip040"
@CategoryID
```

---

Correct:

```sql id="ip041"
@CategoryID INT
```

---

## Wrong Data Type

Bad:

```sql id="ip042"
@CategoryID VARCHAR(50)
```

when CategoryID is numeric.

---

## Too Many Parameters

Keep procedures focused.

---

## No Validation

Always validate critical inputs.
